## 重大平台发现：SetTcp6Entry 是文档幻影（P0.3 调查否决）

M1 偏差表预期「M4 直调 iphlpapi」，实测三重证据否决：

1. SDK 头文件：`iphlpapi.h`/`netioapi.h` 及整个 `um/` include 树**无声明**；
2. 导入库：`Windows Kits\10\Lib\10.0.26100.0\um\x64\iphlpapi.lib` **无符号**
   （MSVC LNK2019 `__imp_SetTcp6Entry` 实证）；
3. DLL：`System32\iphlpapi.dll` 导出表全量枚举（Tcp6 相关 11 个、Set\* 26 个）
   **无此名**——仅 `SetTcpEntry`(v4)/`SetPerTcp(6)ConnectionEStats` 存在。

该 API 只存在于 MSDN 文档页（windows crate 元数据源于导入库，故亦未导出——
三条证据互恰）。**处置拍板**（已登记技术设计「设计拍板记录」第 9 条）：
v6 连接级断开无用户态文档化 API；v6 处置由引擎 Kill（socket 随进程关闭）+
封 IP（netsh/WFP 均支持 v6）兜底；`MIB_TCP6ROW` 行构造与单测保留锚定 MIB 布局。
NSI 未公开接口方案超出「文档化用户态 API」设计边界，暂不采用。

附带勘误：M1 报告所记「GetPerTcpConnectionEstats」为大小写笔误，实为
`GetPerTcpConnectionEStats`，windows 0.61 已导出（P1.5 直接使用）。

## 评审记录（独立 subagent 静态审查）

范围 `git diff abd2ee8..HEAD`（9 提交，含评审修复）。发现 1 高危 + 4 中危 +
5 低危 + 4 建议。**高/中危 5 项已当场修复**（1f3c411）：

| 级别 | 发现 | 修复 |
|---|---|---|
| 高危 | estats ROD 缓冲 16B < `TCP_ESTATS_DATA_ROD_v1` 实际 24B（含 DataSegsOut/In 各 4B）：内核按版本校验会恒失败，且 Err 语义是「移除连接」——全部活跃连接被批量误删，场景 C 静默自毁 | 缓冲 24B；区分 ERROR_NOT_FOUND(移除)/其他 rc(保留重试) |
| 中危 | WFP 子层随动态会话添加：会话 A 关闭删子层，会话 B 过滤器悬空、封禁提前失效（同 IP 连续封禁必触发） | 子层改持久会话一次性装配（进程内 AtomicBool + 内核侧幂等） |
| 中危 | 服务 CWD 为 System32：config.toml/harnessguard.db 会落系统目录 | service_main 切换 CWD 到 exe 目录 |
| 中危 | 服务模式 token 随机生成且 println 无人可见（Session 0） | token 落盘 exe 目录 web-token.txt |
| 中危 | 停机序列「执行器自然结束」因果不成立（ETW 线程常驻持有 etw_tx）；writer 冲刷靠固定 sleep 无汇合 | spawn_writer 返回 JoinHandle 限时汇合；注释如实改写 |

审查确认无缺陷项：probe 布局/循环（40B 条目 x64 无 padding、64MB 双上限）、
enforcer 字节序、LRU 指针链接、SSE 鉴权矩阵与帧编码、sc 语法拼法、锁纪律

## 复验关注的风险点（诚实披露）

- estats 的 `ERROR_NOT_FOUND=1168` 判定基于文档语义，实机若以其他码表示
  「连接不存在」，Transient 分支会保留登记（不误删，但该连接不再补计直至
  ETW disconnect 兜底移除）——复验时留意 `[conn-estats] Get rc=` 日志；
- WFP v6 条件的 `FWP_V6_ADDR_AND_MASK.addr` 字节序按 API 文档传 octets 原样，
  实机请用 v6 目标封禁核验方向性；
- 探测的 150ms 限流在极端 burst 下会主动放弃补名（防回调线程饿死）——
  命中率数字以 `file_probe_tried/hit` 为准，不要以 unknown 清零为预期。
