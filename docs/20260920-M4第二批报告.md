### P0-1 estats 本机降级（51b58ba + a74dd3a 收敛修复）

- 模块头注释按复验定案重写：**ETW send 事件为字节计数主路径**（99 条累计
  5.0MB 实证），estats 降为 best-effort 补充；Win 26100 `Set` 即 rc=50 事实入注。
- `EstatsGate` 门控（纯逻辑）：Set 失败 → 该连接标记不可用并**跳过后续轮询**
  （不再每秒空调用刷 rc=50 日志，每连接仅告警一次）；Get 暂时失败保留重试。
- 评审 M1 修正：被降级连接走 Skip 后看不到 Gone（disconnect 侧移除对 estats
  线程不可达），每轮按 `monitored_quads` 快照**收敛清理** gate/sampler 三表
  ——四元组复用的新连接在旧标记被清后重新尝试一次；同时解决无界增长（评审 M3）。
- 单测 6 例（门控矩阵 + 收敛）。

### P0-2 TaskScheduler 归因竞态（74c98f2 + df01a03 注释修正）

- 根因照复验报告：106 事件到达时发起 cmd 常已退出，实时扫描必 miss。
- 修复：`try_emit_exec` 时把 cmdline 含注册工具特征（schtasks /
  Register-ScheduledTask / RegisterTask）的进程快照进候选表（容量 64、时效
  120s、同 pid 覆盖）；归因链扩为四级：事件 pid（ProcTable 在表即采——事实
  归因）→ 实时扫描（限监控树）→ **缓存候选**（detail 附 cmdline 供人工核对，
  标注"缓存归因（进程已退出）"）→ 0。
- 诚实披露（评审 M2）：候选登记**无法限树**（Exec 时刻 ETW 线程拿不到树身份，
  树判定在引擎侧规则落地后）、取最新候选不看任务名——树外进程的注册事件可能
  归因到 120s 内最新树内候选；缓解：detail 附 cmdline、Persistence 恒为 Audit
  （不触发 Kill/封禁处置）。结构性修法（引擎侧登记候选）入下方待修清单。
- 附带：141 事件单列"删除"语义（待修 4）。
- 单测 4 例（特征矩阵 / 容量 / 时效 / 同 pid 覆盖）。

### P0-4 FILEOBJ_CAP 拍板（a937d0d + a74dd3a 修正）

核算：200k ×（48B slab + ~16B 索引 + NT 路径 ~80B）≈ 26–29MB，超 §10 原
"平台事件源 5–15MB"档。**拍板：维持 200k、修订预算表**（拍板记录第 10 条）：
① 定案 3 后 Name 缓存命中是文件路径解析唯一现实主路径，容量直接决定 burst
unknown 率；② 核减 64k 会重演 M1 整表清空教训且无实测数据支撑；③ 100MB 硬
约束内（修订后合计 ~54–83MB，余量 ≥17MB）。estats 行按逐轮收敛后事实修正
（≤262k × ~30B ≤ 8MB，原"262k×16B"表述未含门控与哈希开销且收敛前实际无界
——评审 M3）。**实机 RSS 复验列入清单**。

### P1-5 Security 4663 通道：评估结论 + opt-in 实现（2a4cd65 + df01a03 修复）

**评估结论**（调研实证，来源见提交与拍板记录 11）：

| 路径 | 结论 | 依据 |
|---|---|---|
| ETW 直连 Security-Auditing provider | ❌ 不作主路径 | undocumented：仅 SYSTEM、搭 OS 的 EventLog-Security 会话（krabsetw 官方示例与 issue 实证；MS Learn 无该 provider 消费文档） |
| **EvtSubscribe push（采用）** | ✅ | 文档化（winevt）：Security 通道 + XPath 过滤 4663，管理员/Event Log Readers 权限，实时回调 |
| 启用端 auditpol + SACL | 侵入性高 → **默认关、显式 opt-in** | auditpol 改系统级审计策略；SACL 命中产生 Security 日志增长；SACL 写入需 SeSecurityPrivilege（已启用） |

实现：`sec_audit.rs`（订阅 → XML 渲染 → 解析 ObjectName/ProcessId/AccessMask →
watch_paths **分量边界**前缀过滤 → `emit_file_event` 复用引擎判定链含监控树
早过滤）；`audit_setup.rs`（`enable/disable-file-audit` 子命令：特权显式启用
（评审 M-1）→ SACL 合并/撤销（SetEntriesInAclW，失败回滚——评审 M-2）→
auditpol（子类别 GUID 免本地化差异）→ config `[file_audit]` 更新）；xml
解析最小实现（实体解码含双重解码防护）。

REVOKE_ACCESS 披露（评审 L-4）：停用会移除 Everyone **全部** ACE（含既有
允许型），非仅本工具写入的审计 ACE——模块注释与提示如实声明。

验证级：单测 7 例（解析/掩码/前缀/配置/ACE 构造）；订阅与 auditpol/SACL
系统效果**待实机复验**（用户配合 UAC + 目标目录）。

### P1-6 停机序列完整化（220bd9a）

- `EtwInner.tx`：OnceLock → `Mutex<Option<Sender>>`；`EventSource::run` 将
  Sender **完整移交** inner（源线程不保留克隆——否则 close 后引擎 recv 永不
  返回）。
- 停机四步（时序日志逐步可观测）：回收 ETW 会话 → `close_channel()` + 释放
  main 侧 etw_tx（引擎排空缓冲后自然返回 → 执行器随 out_rx 关闭退出）→
  运行时 3s 收尾（排水+兜底）→ writer 汇合冲刷（3s 兜底）。
- 评审确认：estats/runkey/sec_audit 均经 inner.emit，通道关闭后静默，回调
  线程不中断；执行器不再依赖超时强制收尾（原评审披露的限制解除）。
- 待实机：`sc stop` 观察日志四步顺序与总时长。

### P1-7 自保护 ACL（c8dd915 + df01a03 M-3 修复）

- `acl.rs`：`apply_dacl`（SetEntriesInAclW + SetNamedSecurityInfoW 受保护
  DACL 切断继承）→ `protect_file`（仅 SYSTEM+Administrators 完全控制）；
  `check_protected`：允许型 ACE 全限两受托者、**继承 ACE 判未保护**（评审
  M-3 fail-closed）、混入非允许型 ACE 判未保护。
- 应用：install 时对已存在三件套；**服务启动自检**（未保护 → 告警并自愈，
  覆盖首次启动新建的 db/token 与每次重写的 web-token.txt）；控制台模式不启用。
- 单测 2 例（三态往返 + 还原；非提权进程实跑 FFI——owner 恒有 WRITE_DAC）。
- LocalSystem 部署形态待实机复验。

### P1-8 服务日志落盘（5b24741 + df01a03 L-1/L-2 修复）
