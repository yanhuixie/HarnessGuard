## 实机暴露并当场修复的缺陷（3 项，57d0385）

| 缺陷 | 现象与定位 | 修复 |
|---|---|---|
| auditpol 子类别 GUID 错误 | 原写 `{0CCE9216-…}` 本机 /get 实测映射"**注销**"（开错子类别，File System 从未启用 → 轮 C/E2 无 4663）；外部多源核对正确值 `{0CCE921D-…}`，本机 /get 确认显示"文件系统" | 常量替换 + disable 提示占位符展开。与第一批 TaskScheduler GUID 同型教训：**GUID 以本机枚举实证为准** |
| 4663 XML 属性单引号 | EvtRender 真实输出 `Name='ProcessId'`（单引号），xml_field 只匹配双引号 → 解析全败（轮 F 日志 9 条"解析失败"+完整 XML 实证）；单测自造双引号样例锚定了错误格式 | 双引号兼容 + **真实格式样例回归锚定**（截自实机事件） |
| NtDuplicateObject 显式权限被拒 | 待修 6"改进"（显式 FILE_READ_ATTRIBUTES）实测 STATUS_ACCESS_DENIED=0xC0000022（轮 D 诊断日志实证：跨进程请求源句柄掩码外权限被拒）——方向错误的改进 | 回退 DUPLICATE_SAME_ACCESS（第一批实证方式）；**待修 6 以实测定案关闭**；保留五级失败诊断日志 |

**定性**：4663 通道把场景 A 的覆盖从"Name 关联丢失"推进到"**投递延迟 vs 进程存活期**"这一更深层的同源困难（探测路径：ETW 投递延迟 > 句柄寿命；4663 路径：EventLog 投递延迟 > 进程寿命）。**修复方向明确**（ProcTable 退出进程短 TTL 缓存，4663 事件按 (pid, 近期退出) 归因），登记下批待修；长命进程场景（真实 harness 常态：守护进程/长任务）不受此竞态影响。
